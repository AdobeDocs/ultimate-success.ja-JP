# ユニバーサルエディターと最新のSSR フレームワークを備えた、高速で編集可能なサイト

現代のweb チームは、マーケターのインコンテクスト編集を犠牲にすることなく、ヘッドレスおよび最新のJavaScriptフレームワークの自由を求めていました。 このセッションでは、Adobe Experience Manager Universal Editorと最新のSSR （サーバーサイドレンダリング）フレームワーク（ReactやNext.js スタイルの設定など）により、SEO （検索エンジン最適化）されたサイトが迅速に提供され、制作者が視覚的に編集する方法を紹介しました。 ユニバーサルエディターをフレームワークベースのアプリに接続する方法、SSRがパフォーマンスとCore Web Vitalsに与える影響、作成者がフロントエンドを壊さずに安全にエクスペリエンスを更新できるようにコンポーネントを構造化する方法について説明しました。 Adobe Experience Manager（AEM）またはEdge Delivery Services（EDS）のプロジェクトを計画または近代化する場合、このウェビナーでは、すぐに利用できる実用的な設計図を提供しました。

>[!VIDEO](https://video.tv.adobe.com/v/3491408/?learn=on&enablevpops)

## 重要な留意点

* **標準EDS サイトとカスタム SSR フレームワークを使用する場合**
標準的なAdobe Experience Manager Edge Delivery Services（EDS）サイトが、ほとんどのプロジェクトで最適なデフォルトである理由と、再構築の代わりに既存のアプリ（ショップやポータルなど）にユニバーサルエディターをレイヤーすることが理にかなっていた場合を理解しました。

* **ユニバーサルエディターがEDSと既存のフレームワークの両方に接続された方法**
ユニバーサルエディターが一般的なAEM EDS設定にどのように適合するか、また、同じ概念がReactまたはNext.js スタイルのSSR アプリケーションに接続する際に適用される仕組みについて説明しました。

* **SSR。EDSのデフォルトとパフォーマンスおよびSEOのニーズのバランスを考慮しました**
EDSのデフォルトを利用できるタイミングと、特定のエクスペリエンスにカスタムサーバーサイドレンダリング（SSR）が本当に必要なタイミングについて説明しました。これには、商品詳細やランディングページなどの価値の高いページのSEOやCore Web Vitalsへの影響が含まれます。

* **開発者やマーケター向けのアプリのパターンが壊れなかったオーサリング**
私たちは、開発者がクリーンで維持可能なコードベースを維持しながら、作成者に安全なインコンテクスト編集機能を提供できるコンポーネントとコンテンツモデルパターンを発見しました。これは、標準的なEDS サイト上でも、既存のフレームワークと統合された状態でも機能します。
